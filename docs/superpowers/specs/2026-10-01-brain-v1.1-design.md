# Brain v1.1: design

Status: superseded by [Second Brain](2026-10-02-second-brain-design.md) (2026-10-02); most of it shipped in 1.1.0 as the Library
Builds on: [Capsule v1](2026-10-01-capsule-v1-design.md)

## Goal
Turn saved Capsules into a small, local **second brain**: notes you can organize, find, and insert into ChatGPT, Claude or Gemini, with the **token cost of every insert shown against the real context window**. That cost display is what no other "AI memory" extension can do honestly.

Success = a user with 50+ notes finds the right one in a few keystrokes, inserts 2–3 of them into a fresh chat, and sees what that costs before sending.

## Principles (unchanged from v1)
- Everything stays in `chrome.storage.local`. No server, no API key, no new network requests.
- Fill, never auto-send: the user presses Enter on every message.
- Truth-in-measurement: token counts are `ESTIMATED` (bundled `o200k_base`; Claude and Gemini tokenize differently). Shown as `~1.2K tokens`, never as exact.

## What changes for the user
1. The **Capsules** tab is renamed **Brain**. A Capsule (AI-written summary) is one way to make a note. The others are a selection or a blank note.
2. Every note has an optional **project** and **tags**.
3. A **search box** and a **project filter** sit on top of the list.
4. Every card shows its **token cost**: `~1.2K tokens · 0.6% of window`.
5. **Multi-select insert**: tick notes and a footer shows `Insert 3 · ~2.1K tokens · 150K left`, turning red when the total exceeds the remaining room.
6. On the **Context** tab at ≥ 65% (HIGH/CRITICAL), a card offers **Save to Brain**, which starts Create Capsule.
7. **Export / Import** of all notes as JSON.

## Flows

### Capture
| Action | Result |
|---|---|
| 📦 Create Capsule | Unchanged (AI writes it, editor opens) |
| ⚡ Quick, 🔀 Hand-off | Unchanged |
| ✂️ Save selection (new) | Editor opens with the selected chat text as body and its first line as title. No AI. |
| ＋ New note (new) | Empty editor (for preferences, facts, a profile, …) |

The editor gains two inputs: **Project** (text with a native `<datalist>` of existing projects) and **Tags** (comma-separated). Saving stores the note's token count.

### Find
- Empty query: pinned first, then newest (`lastUsedAt ?? updatedAt`, descending).
- Query: split into lowercase terms. A note matches only if **every** term appears in its title, tags, project or body. Score per term: title 3, tag or project 2, body 1. Pinned +1. Ties go to the newest.
- Project filter: a `<select>` with "All projects" plus each project in use. Clicking a tag chip puts `#tag` into the search box (matches tags only).

### Insert
- **Insert** on one card: unchanged behaviour (`formatForInsert`), plus `lastUsedAt` is updated.
- **Multi-select**: a checkbox on each card. The footer appears when ≥ 1 note is ticked:
  `Insert N · ~X tokens · Y% of window · Z left` with Insert / Copy / Clear buttons.
  - X counts the **exact text that will be inserted** (`formatManyForInsert`), not the sum of the cards.
  - Y and Z come from the widget's latest view state (`contextLimit`, `remainingTokens`). If the window is unknown, the footer shows `window unknown`.
  - If X > Z, the footer turns red (`Exceeds the room left in this chat`). Insert is still allowed; the user decides.
- One note ticked behaves the same as single Insert.

### Context-pressure loop
On the Context tab, when `healthLevel(percentage)` is HIGH or CRITICAL, a card appears:
`This chat is 78% full. Save it to Brain, then insert it in a new chat.` with the button **Save to Brain**.
That button switches to the Brain tab and runs Create Capsule. If the site's limit blocks chatting, it runs Quick (same logic as today's limit card). After saving, the toast says: `Saved. Open a new chat and Insert it from Brain.`
No automatic navigation to a new chat (out of scope).

### Export / Import
- **Export** downloads `ai-context-brain-YYYY-MM-DD.json` (`{ version: 1, notes: [...] }`) through a Blob and `<a download>`. No `downloads` permission is needed.
- **Import** uses a file input and **merges by id**: when the incoming `updatedAt` is newer, it replaces the stored note; unknown ids are added. The toast reports `12 added, 3 updated, 1 skipped`.
- Import is a trust boundary. Every field is validated and capped (see Data model). Invalid notes are skipped, never partially saved. Text is only ever rendered with `textContent`.

## Data model
One storage key **per note**, `note:<id>`. This removes v1's one-list read-modify-write race (two tabs saving at the same moment).

```js
{
  id: string,                // crypto.randomUUID()
  title: string,             // ≤ 80 chars, default 'Untitled note'
  body: string,              // required, ≤ 100,000 chars
  source: string,            // 'ChatGPT' | 'Claude' | 'Gemini' | 'AI' | 'Import'
  project: string|null,      // ≤ 40 chars, trimmed; '' → null
  tags: string[],            // ≤ 10, each lowercased, trimmed, ≤ 30 chars, no '#' or ',', unique
  tokens: number|null,       // ESTIMATED o200k count of title + body, set on save; null → counted at render
  pinned: boolean,
  createdAt: number, updatedAt: number, lastUsedAt: number|null
}
```

- **List** = `area.get(null)`, filtered to the `note:` prefix. ponytail: reads every key; fine up to a few MB; add an index key if it gets slow.
- **Migration** (on the first `list()`): if the v1 `capsules` array exists, write each item as `note:<id>` with the defaults, **then** remove `capsules`. This is idempotent (same ids give the same keys), so two tabs migrating at once is harmless, and a crash between the two steps just re-runs it.
- **No conversation URL is stored.** PRIVACY.md promises no conversation IDs. Backlinks wait for a privacy decision (v1.2).
- `manifest.json` adds **`unlimitedStorage`**. It shows no install warning and removes the ~10 MB ceiling. If a write still fails, the toast says `Save failed`, the editor stays open, and nothing is lost.

## UI sketch (Brain tab, inside the existing panel)
```text
[📦 Create Capsule] [⚡ Quick] [🔀 Hand-off]
[✂️ Save selection] [＋ New note]
[🔍 Search notes…            ] [All projects ▾]
┌──────────────────────────────────────────┐
│ ☐ 📌 Auth refactor plan                  │
│   Claude · Sep 30 · project: api         │
│   #decision #backend    ~1.2K · 0.6%     │
│   [Insert] [Copy] [Edit] [Delete]        │
└──────────────────────────────────────────┘
…
─────────────────────────────────────────────
Insert 2 · ~2.1K tokens · 1.1% · 150K left
[Insert] [Copy] [Clear]
Export · Import
```
Keyboard: `/` in the open panel focuses search. Enter in search inserts the top result only when exactly one note matches. All new controls need `aria-label`s, like the existing ones.

## Testing
`tests/unit/brain.test.js` (the fake storage area must support `get(null)` and `remove`):
- Migration: v1 list → per-note keys, `capsules` removed, running it twice changes nothing, an empty or missing list is a no-op.
- `normalizeNote`: caps, tag normalisation and dedupe, empty body rejected, wrong types rejected.
- Store: save new / update (keeps `createdAt`), remove, `touch`, two concurrent saves of different notes both survive.
- `searchNotes`: AND terms, field weights, pinned boost, `#tag`, project filter, empty-query order.
- `formatManyForInsert`: one note vs many.
- Import: merge by id with newer-wins, invalid entries skipped, counts reported, non-JSON rejected.

`tests/unit/capsule.test.js`: drop the store tests that moved. Then run `npm test`, `npm run lint`, `npm run build`, `npm run validate`. Manual check on all three sites: create → save → search → multi-insert, the budget footer with a known and an unknown window, and the Save-to-Brain card at ≥ 65%.

## Out of scope (v1.1 → later)
- **v1.2:** auto-suggest notes while typing, fact-extraction prompt, pinned profile note, duplicate detection, backlinks to the source chat (needs a privacy decision), one-click "new chat + insert".
- **v2:** Chrome built-in AI (Gemini Nano) tagging and summaries, semantic search with embeddings, opt-in full-chat archive, sync.
- Not planned: graph view, MCP bridge, cloud backend.

## Open questions
1. Keep the word **Capsule** for AI-written notes in the UI, or call everything a "note"? (Proposed: keep it; a Capsule is a note made by an AI.)
2. Should the budget footer **block** Insert when it exceeds the room left? (Proposed: warn only.)
3. Should Markdown export be added alongside JSON? (Proposed: JSON only; Copy already gives Markdown per note.)
